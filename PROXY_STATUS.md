# Статус Proxy настроек

## Текущее состояние

✅ **SOCKS5 Proxy (1080):** 
- Включен в System Settings
- Порт 1080 занят процессом `io.coress` (Core Tunnel приложение)
- SSH туннель также запущен (PID 34941), но порт уже занят Core Tunnel

⚠️ **HTTP Proxy (8080):**
- Включен в System Settings
- НО: порт 8080 свободен (нет процесса, слушающего этот порт)

## Выводы

1. **Core Tunnel приложение** уже работает и предоставляет SOCKS5 proxy на порту 1080
2. SSH туннель пытается использовать тот же порт (конфликт)
3. HTTP Proxy настроен, но сервиса на порту 8080 нет

## Рекомендации

### Вариант 1: Использовать только Core Tunnel (уже работает)

Если Core Tunnel приложение уже работает и предоставляет proxy на 1080, то:
1. ✅ SOCKS Proxy уже настроен и работает
2. ❌ HTTP Proxy на 8080 не работает (можно отключить)

Отключить HTTP Proxy:
```bash
networksetup -setwebproxystate "Wi-Fi" off
```

### Вариант 2: Использовать SSH туннель вместо Core Tunnel

Если нужно использовать SSH туннель:
1. Остановить Core Tunnel приложение
2. Запустить SSH туннель на порту 1080

Остановить Core Tunnel:
- Закрыть приложение Core Tunnel в macOS

Запустить SSH туннель:
```bash
# Сначала остановить существующий (если есть)
pkill -f "ssh.*-D 1080"
# Затем запустить новый
ssh -i ~/.ssh/id_ed25519_autoro -D 1080 -N -f vladx@46.250.228.229
```

### Вариант 3: Использовать другой порт для SSH туннеля

Если нужно использовать и Core Tunnel, и SSH туннель:

```bash
# SSH туннель на другом порту (например, 1081)
ssh -i ~/.ssh/id_ed25519_autoro -D 1081 -N -f vladx@46.250.228.229
```

## Текущая конфигурация (что уже настроено)

- ✅ SOCKS Proxy: `127.0.0.1:1080` (включен, работает через Core Tunnel)
- ❌ HTTP Proxy: `127.0.0.1:8080` (включен, но сервиса нет)

## Быстрая проверка

Проверить работу SOCKS proxy:
```bash
curl --socks5 127.0.0.1:1080 http://ifconfig.me
```

Если работает - значит Core Tunnel предоставляет рабочий proxy.
