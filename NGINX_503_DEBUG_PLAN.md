# План отладки проблемы 503 в Nginx

## 🔍 Гипотезы о причине 503:

### Гипотеза A: Regex location перехватывает запрос к `/`
**Описание:** Regex location `~* \.(js|css|...)$` может неправильно обрабатывать запрос к корню `/`, интерпретируя его как файл без расширения или конфликтуя с `location = /`.

**Проверка:** Временно отключить regex location для статики.

### Гипотеза B: Проблема с обработкой `index` директивы
**Описание:** Nginx не может обработать `index index.html` в `location = /` или `location /`, возможно из-за проблем с правами доступа к директории или файлу.

**Проверка:** Включить debug логи и проверить сообщения о доступе к файлам.

### Гипотеза C: Конфликт location блоков по приоритету
**Описание:** Порядок location блоков вызывает конфликт, где более специфичный блок (`location = /`) обрабатывается после regex или vice versa.

**Проверка:** Упростить конфигурацию до минимума и проверить работу.

### Гипотеза D: Проблема с правами доступа на уровне файловой системы
**Описание:** Nginx процесс не может прочитать файл или директорию, несмотря на то, что тест `su nginx` показывает успех. Возможно, проблема возникает только при обработке через HTTP.

**Проверка:** Проверить debug логи на сообщения о permission denied.

### Гипотеза E: Cloudflare блокирует или модифицирует запросы
**Описание:** Cloudflare может блокировать запросы к корню `/` или модифицировать Host header, что приводит к неправильной обработке в Nginx.

**Проверка:** Проверить прямые запросы к origin без Cloudflare, проверить настройки Cloudflare.

## 📋 План действий:

1. Включить debug логи в Nginx
2. Временно отключить regex location для статики
3. Упростить конфигурацию до минимума
4. Проверить прямые запросы к origin (без Cloudflare/CDN)
5. Проанализировать debug логи
