# Как применить конфиг Hiddify (Autoro Hysteria2)

Чтобы использовался именно этот конфиг, а не тот, что Hiddify собирает сам из профиля и параметров:

## 1. Включить «Выполнять конфиг как есть»

- Открой **Параметры конфигурации** (Configuration Parameters).
- Включи опцию **«Выполнять конфиг как есть»** / **Execute config as is**.
- Без этого Hiddify игнорирует полный JSON и строит конфиг сам — тогда правки в `hiddify-config-autoro-hysteria2.json` не применяются.

## 2. Подставить полный конфиг из файла

- В профиле Hysteria2 (Autoro) должен быть способ задать **полный конфиг** (например, «Редактор конфига» / «Config as is»).
- Скопируй **весь** JSON из файла `hiddify-config-autoro-hysteria2.json` и вставь в это поле.
- Сохрани профиль.

## 3. Что изменено в конфиге

- **DNS:** удалённый DNS — `77.88.8.8` (Яндекс), запросы идут через **direct** (в обход туннеля), чтобы не было DNS_PROBE_FINISHED_NO_INTERNET из-за обрыва туннеля.
- **Выбор outbound:** по умолчанию сразу **Hysteria2** (без проверки urltest), чтобы не показывало «неизвестный IP» из-за неудачного теста.

## 4. Если всё равно timeout / неизвестный IP

Значит туннель до сервера не поднимается или обрывается. Проверь:

1. **Сервер:** на VPS выполни `docker ps | grep hysteria2` и `docker logs --tail 30 hysteria2` — контейнер должен быть Up и без ошибок.
2. **Сеть:** попробуй с другой сети (мобильный интернет, другая Wi‑Fi) — возможно, провайдер режет UDP 443 или QUIC.
3. **Фаервол:** на роутере/ПК не должен блокироваться исходящий UDP 443 до 46.250.228.229.
