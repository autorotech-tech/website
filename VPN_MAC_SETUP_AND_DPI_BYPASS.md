# VPN на Mac: анализ настройки и обход блокировок провайдера (DPI)

## 1. Анализ текущей настройки VPN

### Сервер
- **VPS:** 46.250.228.229  
- **Протокол:** Hysteria2 (QUIC поверх UDP)  
- **Порт:** 443/UDP  
- **TLS:** сертификат домена autoro.tech (SNI: autoro.tech)  
- **Контейнер:** Docker, образ `tobyxdd/hysteria:latest`, имя контейнера `hysteria2`  

Трафик выглядит как обычный HTTPS/HTTP3 до домена autoro.tech — это уже помогает от части DPI.

### Клиент (Mac)
- **Приложение:** Hiddify (sing-box под капотом)  
- **Конфиг:** `hiddify-config-autoro-hysteria2.json`  
- **Режим:** TUN (весь системный трафик через VPN), DNS через direct (77.88.8.8), остальное через Hysteria2  

### Что может резать провайдер
- **UDP 443** — блокировка или троттлинг QUIC/UDP на 443.  
- **QUIC/паттерны** — распознавание Hysteria2 по фингерпринту.  
- **SNI** — если провайдер блокирует по SNI (autoro.tech).  
- **Таймауты** — обрыв «тихих» UDP-сессий по таймауту.  

Ниже: как проверить трафик (DPI detector) и как настроить клиент на Mac с учётом обхода.

## 2. Анализ трафика: DPI Detector

Чтобы понять, что именно делает провайдер с пакетами (блокировка, троттлинг, сброс по SNI и т.д.), запусти детектор на Mac.

### Запуск (Docker на Mac)

```bash
docker run --rm -it --pull=always ghcr.io/runnin4ik/dpi-detector:latest
```

- Будет предложено выбрать сетевой интерфейс (обычно `en0` — Wi‑Fi или `en1` и т.д.).  
- Детектор начнёт слать тестовые пакеты и смотреть ответы сети (сброс, таймаут, искажение).  
- Результаты покажут, блокируется ли UDP, QUIC, по SNI и т.д.  

### Что смотреть в выводе

- **UDP блокируется** — провайдер режет UDP (в т.ч. 443). Варианты: пробовать другой порт на сервере (например 8443/UDP) или другой протокол (WireGuard, но он тоже UDP).  
- **QUIC/паттерн детектируется** — имеет смысл включить обфускацию на клиенте (см. раздел 4).  
- **SNI блокируется** — не подставлять лишние SNI; убедиться, что SNI = реальный домен (autoro.tech), и при необходимости сменить домен/сертификат.  
- **Всё зелёное** — блокировки по тестам нет; проблемы могут быть на стороне маршрутизации или фаервола.  

После прогона детектора можно скорректировать настройки клиента и сервера по результатам.

## 3. Настройка клиента на Mac (пошагово)

### Вариант A: Hiddify (рекомендуется)

1. **Установка**  
   - Скачай Hiddify для macOS: https://github.com/hiddify/hiddify/releases  
   - Установи приложение (перетащи в «Программы» или по инструкции разработчика).  

2. **Добавление профиля**  
   - Открой Hiddify → «Профили» → «Добавить из буфера обмена» или «Ввести вручную».  
   - Вставь ссылку профиля:
     ```
     hysteria2://hy2-98f20ef9ce8dd981d4283d4781bb7cae@46.250.228.229:443?insecure=0&sni=autoro.tech
     ```
   - Или вручную задай: тип **Hysteria2**, сервер **46.250.228.229**, порт **443**, пароль **hy2-98f20ef9ce8dd981d4283d4781bb7cae**, SNI **autoro.tech**.  

3. **Применение полного конфига (важно)**  
   - Параметры конфигурации → включи **«Выполнять конфиг как есть»** (Execute config as is).  
   - В профиле укажи источник конфига «как есть» и вставь **целиком** содержимое файла `hiddify-config-autoro-hysteria2.json` из этого репозитория.  
   - Сохрани. Так будут использоваться DNS через direct и маршрутизация без лишних rule-set.  

4. **Права и режим**  
   - При первом включении VPN macOS запросит разрешение на установку расширения (VPN/TUN). Подтверди.  
   - Режим работы: **VPN (TUN)** — весь трафик через туннель (кроме DNS, если оставлен detour: direct).  

5. **Проверка**  
   - Включи профиль → открой в браузере https://api.ipify.org — должен отображаться IP **46.250.228.229**.  

### Вариант B: sing-box (CLI) на Mac

Если нужен только консольный клиент без GUI:

1. Установка (Homebrew):
   ```bash
   brew install sing-box
   ```

2. Сохрани конфиг в файл, например `~/autoro-hysteria2.json` — содержимое из `hiddify-config-autoro-hysteria2.json` (то же самое).

3. Запуск:
   ```bash
   sing-box run -c ~/autoro-hysteria2.json
   ```

4. Для работы TUN на Mac могут потребоваться права (sudo) или настройка маршрутов вручную; для простоты обычно удобнее Hiddify.

## 4. Обход блокировки пакетов провайдером (DPI)

### Уже сделано

- **Порт 443/UDP** — трафик похож на обычный HTTPS/QUIC.  
- **TLS и SNI autoro.tech** — выглядит как посещение сайта autoro.tech.  
- **Hysteria2** — протокол с маскировкой под HTTP/3.  

### Что можно включить в Hiddify (экспериментально)

В **Параметры конфигурации** → **Хитрости TLS (экспериментально)**:

- **Включить TLS Padding** — увеличивает размер TLS-записей, может мешать фингерпринту.  
- **Включить фрагментацию TLS** — разбивает запись на фрагменты (размер/задержка по желанию).  

Включай по одному, проверяй стабильность и снова запускай DPI detector — смотреть, изменилось ли поведение провайдера.

### На стороне сервера (при необходимости)

Если DPI detector покажет блокировку UDP 443 или QUIC:

- **Сменить порт:** поднять Hysteria2 на другом UDP-порту (например 8443) и в клиенте указать `server_port: 8443`; на VPS открыть этот порт в UFW.  
- **Проверить MTU:** на проблемных сетях иногда помогает уменьшить MTU (например 1400 или 1280) в конфиге клиента (поле `mtu` в TUN).  

### Рекомендуемый порядок

1. Запустить **DPI detector** и сохранить вывод (скрин или лог).  
2. Настроить клиент по **разделу 3** и убедиться, что без блокировок всё работает (другая сеть / мобильный интернет).  
3. В своей сети включить **TLS Padding** (и при необходимости фрагментацию), снова проверить подключение и при возможности повторить DPI detector.  
4. Если провайдер режет именно 443/UDP — обсудить с хостингом смену порта и открыть его на фаерволе.
