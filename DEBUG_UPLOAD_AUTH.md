# Отладка проблемы авторизации при загрузке файлов

## Проблема

POST запрос к `/api/blog/admin/upload` возвращает 401, хотя заголовок Authorization присутствует в запросе.

## Диагностика

Добавлено логирование в `upload/route.ts` для проверки:
1. Передается ли заголовок Authorization
2. Все ли заголовки доходят до сервера

## Проверка

После перезапуска контейнера:

1. Попробуйте загрузить файл в браузере
2. Проверьте логи:
   ```bash
   ssh -i ~/.ssh/id_ed25519_autoro vladx@46.250.228.229
   docker logs -f autoro-blog-nextjs
   ```

3. В логах должно появиться:
   - "Upload POST - Authorization header: Present" или "Missing"
   - "Upload POST - All headers: {...}"
   - "Upload POST - Admin check failed, authHeader was: ..." (если авторизация не прошла)

## Возможные решения

### Если заголовок отсутствует

Возможно, GCore CDN или nginx-proxy удаляет заголовок Authorization для multipart/form-data запросов.

**Решение:**
1. Проверить настройки GCore CDN - возможно, нужно добавить правило для сохранения заголовка Authorization
2. Или использовать cookie для авторизации вместо заголовка

### Если заголовок присутствует, но авторизация не проходит

Проблема в функции isAdmin или в токене.

**Решение:**
1. Проверить, валиден ли токен
2. Проверить логи Supabase в функции isAdmin

## Проблема с блокировкой для России

GCore CDN не справляется с обходом блокировки для `swoop.autoro.tech`.

Это отдельная проблема, не связанная с загрузкой файлов. Возможные решения:
1. Использовать другой CDN (Bunny CDN, Cloudflare с другими настройками)
2. Использовать VPN/tunnel для обхода блокировки
3. Настроить дополнительные правила в GCore CDN для обхода блокировки
