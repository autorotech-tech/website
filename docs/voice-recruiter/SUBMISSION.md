| Поле | Значение |
|------|----------|
| Публичная ссылка | https://swoop.autoro.tech/voice-recruiter |
| Сервис API | **Autoro/Swoop** (`https://swoop.autoro.tech`) — адаптация вместо ProxyAPI/RouterAI/KodikRouter |

### Адаптация от формулировки школы

- Replit → Cursor + Vite/React в репозитории website
- ProxyAPI → Autoro/Swoop agent-api (`X-API-Key` из Admin → Settings)
- STT: `POST /api/v1/media/transcribe-upload`
- LLM: `POST /api/v1/chat/completions`
- TTS: `POST /api/v1/media/speech` (+ browser `speechSynthesis` fallback)

Первый вопрос: расскажите, пожалуйста, о вашем самом сложном проекте на Django или FastAPI — какая стояла задача, как вы её решали и с какими основными трудностями столкнулись?

**Кандидат:** Меня зовут Алексей, 4 года пишу на Python, Django и FastAPI. Самый сложный проект — API для биллинга: много конкурентных списаний, нужна была идемпотентность и прозрачный аудит операций.

**AI-рекрутер:** Отличный опыт — биллинг обычно требует высокой надёжности. Второй вопрос: как вы решали проблемы конкурентного доступа и обеспечивали идемпотентность операций? Использовали ли транзакции, блокировки, уникальные ключи?

**Кандидат:** Делал API для биллинга, покрывал pytest, деплой в Docker. Для идемпотентности — ключи идемпотентности в заголовках и уникальные ограничения в PostgreSQL, критичные операции в транзакциях.

**AI-рекрутер:** Впечатляет связка pytest + Docker. Третий вопрос: расскажите, как вы выявляли узкие места по производительности и какие изменения дали основной эффект?

**Кандидат:** Оптимизировал SQL-запросы, снижал latency с 800 до 120 мс. Смотрел EXPLAIN, добавил индексы, убрал N+1 через select_related/prefetch и вынес горячие чтения в Redis.

**AI-рекрутер:** Снижение latency почти в 7 раз — сильный результат. Четвёртый вопрос: как вы использовали Celery и Redis? Какие гарантии доставки задач применяли и как обрабатывали повторные запуски?

**Кандидат:** Работал с Celery, Redis, PostgreSQL, немного с asyncio. Обычно at-least-once + идемпотентные воркеры; для критичных задач — ack late и дедуп по task id.

**AI-рекрутер:** Понял. Пятый вопрос: какие практики code review вы считаете наиболее полезными? Приведите пример, когда ревью помогло избежать серьёзной ошибки.

**Кандидат:** Ищу команду с сильной инженерией и code review. На ревью ловили отсутствие идемпотентности в webhook-обработчике платежей — добавили уникальный ключ события и тесты на повторную доставку.

**AI-рекрутер:** Спасибо за ответы. На этом вопросы закончены — ниже итоговая оценка.

===ИТОГ===
Общая оценка: 7/10 — уверенный middle с релевантным стеком и сильными кейсами по производительности; ответы местами краткие, не хватает глубины по конкурентности.
Сильные стороны: опыт биллинга; измеримый результат по latency; стек Django/FastAPI/PostgreSQL/Celery/Redis; внимание к тестам и Docker; понимание ценности code review.
